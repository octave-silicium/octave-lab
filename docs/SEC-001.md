# SEC-001 — Security engineering and release assurance

Status: staged on governance branch; no release or security qualification. Keep public research evidence and private core/data separate. No private key, client data, restricted raw material or private strategy in public Git, CI artifacts, logs or test fixtures.

## A — Baseline and narrow hardening
Pin the three actions in the existing read-only governance workflow to official tag resolutions (checkout v4, setup-python v5, upload-artifact v4), retaining read-only permissions and disabling credential persistence. Tag-to-SHA verification is provenance, not independent upstream code audit. Re-evaluate pins on updates; preserve known-good versions and tests.

Run deterministic, bounded Git scan on pinned public ancestry; report only aggregate token-shape counts, never matching values/locations. Triage workflow references, explicit permission indicators, direct pushes, install commands and artifacts. No assumption that regex or zero candidates establishes security. No automatic credential rotation or publication.

## B — Remaining controls
Map actual workflow execution/data rights and isolate snapshot writes before enabling main protection. Do not activate changes to all collection workflows in one push. Verify required checks, least privilege, no force pushes/deletion, review path and restore. Administrative settings need owner-side action when integration lacks permission. Verify private repository independently before transferring sensitive code. Never use a public Actions runner as a confidential data vault. Review dependency inventory, lock/pin actual runtime dependencies, SBOM, approved artifact paths and retention, secret scans and security tests. Review all public output paths and deny unknown/unqualified releases. Client isolation, provider data handling, access control, recovery and threat modelling are prerequisites before any client data.

## FINOPS
Use existing read-only CI, no additional paid service. Stage remaining changes by risk and actual product need; private infrastructure and enterprise auth are not implemented speculatively. The engineering register retains OPEN statuses until scoped evidence is accepted.

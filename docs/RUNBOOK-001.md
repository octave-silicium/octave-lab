# RUNBOOK-001 | Exploitation privée
## Décision de déploiement
Un hôte local dédié ou un VPS privé doté d'un volume persistant et sauvegardes indépendantes est requis. Aucun hôte de production ni volume permanent n'est actuellement provisionné. Ne pas utiliser GitHub Actions public comme coffre de données privées. Drive contient des fichiers sources et la documentation, pas un service SQLite transactionnel ; ne pas synchroniser une base ouverte dans Drive. Pour exploitation solo initiale privilégier une machine existante si disponibilité suffisante ; VPS à décider selon budget, localisation, sauvegarde et contrôle d'accès. Pas de service externe commandé ni de coûts engagés.
## Initialisation, Python 3.11
Cloner le dépôt, installer Python ; créer dossier privé hors dépôt avec accès limité au compte de service (POSIX 0700 ; sous Windows, contrôler ACL NTFS). Ne pas exposer le répertoire par serveur de fichiers. Exécuter `python -m pipeline.vault_ops --vault /chemin/prive collect-due --force` ; revoir candidats, droits et qualité avant promotion explicite `python -m pipeline.data_vault --vault /chemin/prive promote SOURCE SHA --expected NONE --reason INITIAL_REVIEW`. Pas d'approbation globale implicite. Vérifier `health` et `verify`. Copier un snapshot G2 fermé sur volume privé, conserver son empreinte indépendamment, vérifier avant usage. La première commande ne couvre ni les sources manuelles ni O*NET bundle.
## Serveur
`python -m pipeline.explorer --vault /chemin/prive --private-db /chemin/prive/lot.sqlite --private-sha SHA` ; accès 127.0.0.1:8765 uniquement. Le mode --vault est incompatible avec --live, n'utilise ni téléchargement à la volée ni ancien lecteur comme secours. Les sources sans actif approuvé sont absentes. Ensemble d'empreintes actives fixé au démarrage ; données relues avec validation et hash. Promotion en cours de session ne change pas les empreintes. Redémarrer explicitement pour nouvelle sélection. Une sauvegarde de vue portant une autre empreinte est refusée ; pas encore de sélection d'ancien millésime depuis interface. Timestamp du coffre = première validation/intake, pas publication et pas nécessairement téléchargement originel ; champ vintage_kind explicite. L'interface emploie encore le mot collecte, correction UX nécessaire. Les objets restent conservés, ne pas purger pendant sessions. Aucun service public, authentification multi-utilisateur non implémentée. Accès distant à qualifier (tunnel privé ou SSH avec contrôle d'accès, jamais port public).
## Maintenance
Planifier sur l'hôte `python -m pipeline.vault_ops --vault /chemin/prive collect-due` chaque jour ; intervalle et reprise gérés par le journal. Utiliser un seul processus de collecte (verrou système/gestionnaire de tâches), environnement fixe, journaux privés ; code retour non nul = incident. Aucune planification hôte activée par cette documentation. Revue des nouveaux candidats, contrôle de publication et comparabilité avant promotion ; relancer serveur si nouvelle sélection approuvée. Sauvegarde `backup /chemin/backup-nouveau`, conserver SHA séparément ; copie de la sauvegarde fermée vers stockage indépendant, chiffré si nécessaire selon droits ; test de restauration dans nouveau dossier avec `restore /chemin/backup --sha256 SHA`. Ne pas copier le fichier SQLite ouvert. Retention et droits à définir avant production.
## Critères de passage
Hôte et volume réellement provisionnés, permissions vérifiées, neuf jeux et snapshot G2 approuvés, sauvegarde indépendante/restauration, déclenchement planifié réel et alertes reçues, redémarrage et lecture des versions épinglées vérifiés, audit réseau local et revue de droits. Gate production non atteint. Les tests CI ne le remplacent pas.

## Explorateur
`pipeline/work_explorer.py` et `explorer/work.html` / CSS / JS : trois référentiels distincts, recherche libellé/code accent-insensible, pagination, profils et relations typées, source et localisateur de ligne ; pas de conversion de compétence en tâche, d'action atomique ou de score IA. O*NET : tâche puis DWA ; ROME : fiche/appellation/compétence/savoir/contexte ; ESCO : essentiel/optionnel et parent natif si base enrichie. La page /work et ses routes sont désactivées sans manifeste. Le serveur local reprend les gardes Host/Sec-Fetch-Site et CSP, aucun export. Les utilisateurs locaux autorisés peuvent lire les données : pas de service multi-utilisateur.
Démarrer depuis le dépôt : `python -m pipeline.explorer --work-manifest /chemin/prive/work_manifest.json` (facultatif --vault et --private-db selon RUNBOOK-001). Ouvrir http://127.0.0.1:8765/work. Manifest JSON local : clés optionnelles onet, rome, esco ; onet contient les quatre clés de FILES dans work_graph.py, chacune objet path et sha256 ; rome objet path (ZIP officiel) et sha256 ; esco objet path (SQLite privé fermé) et sha256. Fournir les fichiers déjà collectés, contrôler les empreintes contre les audits et conserver le manifeste hors dépôt. Ne pas présenter un timestamp de chargement comme date de publication. Le manifeste ne constitue pas une approbation de publication.
